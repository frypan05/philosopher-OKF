How bit manipulation, binary conversion, scheduling, and memory allocation work

Everything a computer stores is a pattern of 0s and 1s: numbers become bit patterns by place value, and a handful of bitwise operations change individual bits directly. The operating system repeats the same idea at a larger scale — it saves each process's state as bits, chooses who runs next with a fixed rule, and splits memory into equal blocks so every process gets a protected share.

A bit is a switch, and binary is counting with them

A bit is one binary digit: a switch that is off (0) or on (1). Eight of them make a byte, and a 64-bit machine moves 64 at a time. Every value in memory — a number, a character, an address — is one of these patterns.

Binary conversion is place value with base two. Each digit counts a power of two, so 1011010 reads as 64 + 16 + 8 + 2 = 90 [Number Bases]. Going the other way, peel off the largest power of two that fits: 118 leaves 64, then 32, 16, 4, and 2, giving 1110110 [Number Bases]. This is also why memory sizes are powers of two: n bits hold exactly 2n different values [Number Bases].

Conversion never changes the quantity — only the place values the digits sit in.

Bitwise operations are yes/no questions applied to every bit at once

Five operators cover almost everything: AND, OR, XOR, NOT, and the shifts. AND returns 1 only where both bits are 1 — the mask question "is this bit set?"; OR sets a bit wherever either side has 1; XOR flips a bit exactly where the two sides differ; NOT inverts every bit [Bitwise Operators]. A shift slides every digit one or more places, the same move as multiplying or dividing by a power of two when nothing falls off the end: 45 shifted left once becomes 90, shifted right once becomes 22.

Concretely, with a flag byte 00000101: setting bit 1 is flags | (1 << 1), which gives 00000111; clearing bit 0 is flags & ~(1 << 0), which gives 00000110; testing bit 2 is (flags >> 2) & 1, which gives 1 [Bitwise Operators]. Because a machine word's bits are independent, one instruction checks or updates every flag at the same time.

A mask is a yes/no question written in binary.

The scheduler is the same decision problem, scaled up to processes

A process is a running program. The OS keeps each process's state — saved registers, the program counter, memory maps — in a process control block, and moves processes between Running, Ready, and Blocked (waiting for an I/O event) [Process, §4.4]. One core runs one process at a time, so whenever the current process blocks or its slice ends, the scheduler takes the next process from the Ready queue [Process, §4.5].

Policies differ by what they optimize. FCFS runs jobs in arrival order and lets one long job block everything behind it; SJF and STCF minimize turnaround (arrival to completion); round robin gives each process a short time slice, which minimizes response time (arrival to first run) at some cost to turnaround [CPU Scheduling, §2]. Job lengths are never known in advance, so real systems use multilevel feedback queues that raise or lower priority from observed behavior [CPU Scheduling, §2].

No scheduler knows how long a job will run, so the good ones keep revising their guess.

Memory allocation solved fragmentation by giving up contiguity

The oldest allocators carved memory into variable-sized holes: first-fit takes the first hole big enough, best-fit the smallest that fits, worst-fit the largest [Contiguous allocation]. All three leave external fragmentation — many small holes, none big enough for the next request — and no choice of policy removes it.

Paging gives up contiguity instead. Physical memory is split into fixed-size frames and each process's memory into same-sized pages (powers of two, classically 512 bytes to 16 MB) [Paging]; a page table maps every page to any free frame, so a process's memory can be scattered [Paging]. The address itself splits into page number and offset — field extraction with the same shift-and-mask logic as flags >> 2 & 1 [Paging]. What is left is internal fragmentation: a sliver wasted at the end of each allocation.

Fixed pages trade a sliver of wasted space for an allocation problem that disappears.
