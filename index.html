Any topic in, one reading guide out

phil-OKF is a skill for AI agents that turns any question into a single self-contained HTML page: minimal, white, research-paper style, every claim tagged to a source that resolves. The whole skill is one small bundle — an eight-step workflow, a domain classifier, a page template, and twelve study domains — and each file is read only when the depth of the question needs it.

The skill is built on OKF

OKF — the Open Knowledge Format — is plain Markdown with YAML frontmatter: one folder of typed files, no SDK, no build step, readable by any model that can open a file. This repository is a conformant bundle: okf/index.md declares okf_version at the root, every file carries a type, and scripts/validate.sh checks the rules and the links [OKF].

The format is why one skill serves every surface — a skill agent walks the folder file by file, and philosopher.md flattens the same bundle into a single file for chats that cannot fetch several [SKILL].

Plain Markdown. No SDK. Any model can read it.

One question becomes one cited HTML file

The agent classifies the question to a single primary domain, loads only the files that depth requires, researches inside fixed caps, and writes the whole page in one file-creation call [Workflow]. The chat reply is at most two sentences — the path and what the page covers — never the page itself [Workflow]. Sources that were not retrieved this session are never cited: a page with three correct references beats a page with twelve doubtful ones [Source policy].

One file. White theme. No fabricated sources.

The token budget is fixed before the run starts

Four things consume context in a run: the bundle files it reads, the sources it fetches, its own reasoning, and the HTML it writes. The ceiling over all four is not one number — it follows the depth your words ask for [Depth budgets], defaulting to standard when the question says nothing [Defaults].

What you ask forDepthWhole-run budget
"quick", "what is" — a fast answerbriefabout 12k tokens
A normal question (the default)standardabout 25k tokens

Whichever row you land on, the levers are the same: searches and fetches capped by depth (table above), three to five bullet notes after each fetch instead of re-reads [Fetching], the page written in one file-creation call, and a plan of one line per item [Writing]. A finished run prints no token statistics — staying under the ceiling is the workflow's job, not the reader's [Context report].

Budgets are rules in the workflow, not intentions in a prompt.

What this is not

Not a static-site generator, a wiki, or a chat log: one question produces one page, with no JavaScript, no analytics, and no network calls when opened. It is also not a research engine — reference counts are hard caps, and citations come from sources actually retrieved in that run.
