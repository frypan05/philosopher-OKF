Stacks, queues, heaps, trees, and graphs

Stack, queue, binary heap, binary search tree, and graph are the five data structures this page defines, with exact costs: O(1) for stack push and pop, O(log n) for heap insert, O(h) for a search in a tree of height h, and Θ(V+E) for breadth-first search over V vertices and E edges. Each section gives a definition, one worked trace with real values, and one failure case, and every cost is worst case for the standard array-backed or adjacency-list implementation.

Stack: push, pop, and peek each cost O(1), scanning costs O(n)

A stack returns the element that arrived last: push adds an element to the top, pop removes and returns the top element, and peek reads the top element while leaving it in place, so the service order is last in, first out. The standard implementation stores the elements in one array behind a single integer, the top index. [Operations]

Trace: the stack starts empty. push 4 leaves [4], push 7 leaves [4,7], push 2 leaves [4,7,2] with 2 on top. pop returns 2 and leaves [4,7], peek returns 7, pop returns 7 and leaves [4], pop returns 4 and leaves []. Seven operations, each writing or reading one slot. One more pop on the empty stack fails: Python raises IndexError.

No other element ever moves. push, pop, and peek are each O(1) worst case, and a scan for a value below the top reads up to n slots, O(n). [Operations]

Failure case: a fixed-capacity array. Trigger: a push when the top index already sits at the last slot, so the element has nowhere to go and the run reports overflow (stack overflow). [Operations]

Queue: a ring buffer makes enqueue and dequeue O(1) each

Elements leave a queue in the order they arrived: enqueue adds an element at the rear, dequeue removes the element at the front, and the service order is first in, first out. [Lesson 8]

The fast implementation is a ring buffer: a fixed array of capacity c with a front index and a rear index. enqueue writes at rear and then sets rear = (rear + 1) mod c; dequeue reads at front and then sets front = (front + 1) mod c. The modulo wraps each index back to slot 0 instead of past the end of the array, and no stored element ever moves. [Lecture 6]

Trace: capacity 8, empty buffer. enqueue A, B, C, D fills slots 0 to 3. Dequeue returns A and advances front to 1. Enqueue E, F, G, H fills slots 4 to 7; after writing H at slot 7 the rear index wraps, (7 + 1) mod 8 = 0, pointing at the slot A left. Seven elements are held, front = 1, rear = 0, and none of them moved. [Lecture 6]

With wrap-around indexing, enqueue and dequeue are each O(1) worst case: one write or read and one index update. [Lecture 6] [Queue types]

Failure case: an array queue that keeps the front element in slot 0. Every dequeue must shift the remaining n - 1 elements one slot toward the front, so one dequeue is O(n) and draining n elements is O(n²). Trigger: repeated dequeue from a queue without wrap-around.

Binary heap: O(1) minimum, O(log n) insert and extract

The binary heap stores n keys in one array arranged as a nearly complete tree, ordered only between parents and children: for every index k, heap[k] ≤ heap[2k+1] and heap[k] ≤ heap[2k+2] for a min-heap. Siblings and separate subtrees carry no order relative to each other. The tree is complete through the last level, so the children of slot k sit at slots 2k+1 and 2k+2 and its parent sits at slot (k−1)/2 rounded down: index arithmetic instead of pointers. [Heap invariant] [Lesson 8]

The layout fixes the costs. The invariant puts the smallest key at heap[0], so reading the minimum is O(1). Insert (heappush) appends the new key at the end and sifts it upward, one swap per level, and a complete tree of n keys is log2 n levels deep, so insert is O(log n) worst case. Extract (heappop) moves the last key into the root and sifts it downward: also O(log n). heapify(list) rebuilds a valid heap from an arbitrary list without the n separate inserts that would cost O(n log n). heapify(list) runs in O(len(list)) time, linear in the number of keys. [Source] [heapify]

import heapq
h = [5, 3, 8, 1]
heapq.heapify(h)         # [1, 3, 8, 5]  O(len(h))
print(heapq.heappop(h))  # 1, leaves [3, 5, 8]  O(log n)
heapq.heappush(h, 0)     # [0, 3, 8, 5]  O(log n)
print(h[0])              # 0, the minimum  O(1)

Trace: [5,3,8,1] heapifies to [1,3,8,5], and heap[0] is 1. heappop returns 1 and leaves [3,5,8]: two comparisons sift 5 down one level. heappush(h, 0) appends 0, swaps it with 5, then with 3, and stops at the root: [0,3,8,5]. The array holds the same five keys throughout; only their positions change. [Heap operations]

A priority queue removes the element with the highest priority on each removal regardless of arrival time, while an ordinary queue removes the oldest element first. A binary heap implements the priority queue: insert O(log n), removal of the priority element O(log n), and reading it O(1) at heap[0]. [Queue types] [Source]

Failure case: a lookup by value. The heap supports two fast operations, reading the smallest key and placing a new one, and gives no fast path for a named key: finding or deleting the key 8 inside [3,5,8] inspects every slot, O(n), since sibling keys carry no order that would let a scan skip a subtree. Trigger: any search by value instead of by minimum. [Heap invariant]

Binary search tree: search walks one path, O(h)

In a binary search tree, every key in a node's left subtree is smaller than the node and every key in its right subtree is larger. Search, insert, and delete compare against one node per level and follow one path from the root toward a leaf, so each costs O(h), where h is the height of the tree. [Source]

Trace: insert 8, then 3, then 10, then 1, then 6. The root is 8, 3 and 10 hang below it, 1 sits left of 3, and 6 sits right of 3, so the height is 2. Searching for 6 compares against 8 (smaller, go left), against 3 (larger, go right), and against 6: three comparisons along one path, O(h).

A balanced tree of n keys has height log2 n rounded down, so search and insert are O(log n). An AVL tree forces that height: after each insert or delete it rotates nodes until sibling subtrees differ in height by at most one, which holds the height at or below about 1.44 log2 n, and one insert is one ordinary tree insert plus O(1) rotations per level, still O(log n). [AVL notes] [Source]

A heap orders each parent against its children and nothing else, while this tree orders every key along a path, so one comparison can discard a whole subtree. [Heap invariant] [Source] Fed keys in ascending order, 1, 2, 3, 4, 5, every insert attaches to the rightmost node: the tree becomes a chain of n nodes with height n − 1, and search degrades from O(log n) to O(n). Trigger: sorted input, which a bulk import of ordered records produces. [Source]

Graph: breadth-first search runs in Θ(V+E) on an adjacency list

Two vertices in a graph are joined by an edge, and a graph with V vertices and E edges has two standard layouts. An adjacency list stores, for each vertex, a list of its neighbors, so the whole graph takes Θ(V+E) space, proportional to the edges present. An adjacency matrix stores a V by V table of edge presence, Θ(V²) space whether E is close to V or close to V². [Notes 2] [Lesson 8]

Breadth-first search starts from one vertex held in a queue, marks it, then repeatedly dequeues a vertex and enqueues each neighbor it has not seen. The vertices leave the queue in rings of non-decreasing distance from the start: ring 0 is the start itself, ring 1 its neighbors, ring 2 their neighbors. Each vertex is enqueued at most once, so the queue holds at most V entries, and each adjacency list is scanned once, so the scan reads 2E neighbor entries in an undirected graph. [Notes 2]

Trace: six vertices, A joined to B and C, B joined to D, C joined to E and F, five edges. The queue starts as [A]. Dequeuing A enqueues B and C, so ring 1 opens with [B, C]. Dequeuing B enqueues D, dequeuing C enqueues E and F, so ring 2 opens with [D, E, F]. Those three have no unseen neighbors, the queue empties, and all six vertices have been visited in three rings. [Notes 2]

One run of breadth-first search costs Θ(V+E) on an adjacency list. Depth-first search swaps the queue for a stack and keeps the same Θ(V+E) cost. [Notes 2]

Failure case: the layout rather than the search. Take V = 10,000 vertices with E = 10,000 edges, an undirected sparse graph: its adjacency list holds 2E = 20,000 neighbor entries. The matrix for the same graph holds V² = 100,000,000 cells, which is 100 MB packed at one byte per cell and 800 MB at 8 bytes per cell, against about 20,000 entries for the list. Trigger: any graph whose edge count stays far below V². [Notes 2]

What this does not show

The page traces five structures and one traversal. Depth-first search gets one line (swap the queue for a stack, same Θ(V+E) cost), and shortest-path algorithms such as Dijkstra's algorithm and A* are absent entirely. Balanced trees stop at AVL: the rotations are named with their effect on height but not traced, and red-black trees, B-trees, and splay trees are absent. Hash tables, with their load factor and collision handling, are absent too.

All costs are big-O worst case for single-threaded, in-memory structures. Constants and memory-hierarchy effects never appear, so the page gives no wall-clock number, and concurrent variants such as lock-free stacks and lock-free queues sit outside it.
